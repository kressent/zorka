# 📷 Фото улова + распознавание рыбы — план (делаем вместе)

> Почему не сделал ночью «вслепую»: фото завязано на камеру телефона и хранилище — это
> нужно **тестировать на реальном устройстве**, а распознавание требует выбора модели.
> Поэтому — готовый план, реализуем вместе за один заход с проверкой на твоём телефоне.

## Этап 1 — фото в дневнике (просто и полезно, ~1 вечер)
Ценность сразу: у улова появляется фото → красивее карточка, живее лента, и это «топливо»
для будущего распознавания.

- **Захват:** `<input type="file" accept="image/*" capture="environment">` — открывает
  камеру/галерею на телефоне.
- **Сжатие:** рисуем в `<canvas>`, ужимаем до ~800px, JPEG ~0.6 → 40–80 КБ (чтобы не
  раздувать хранилище).
- **Хранение:** локально, отдельным ключом `zorka_photos` = { entryId: dataURL } —
  **не** пихаем в синхронизируемый объект записи (иначе раздуём облако). Облачное фото —
  отдельно и позже, через Supabase Storage (по желанию, приватно).
- **Показ:** превью в редакторе записи, миниатюра в списке дневника, фон/врезка в
  карточке улова (`catchcard.js`).
- **Аккуратно:** ловить `QuotaExceededError` (память устройства), давать удалить фото.

Что протестировать с тобой: съёмка на Android и iPhone, ориентация (EXIF-поворот),
размер localStorage.

## Этап 2 — распознавание рыбы по фото (снимает трение → кормит данные)
Цель: сфоткал → приложение предложило вид → один тап, запись готова. Меньше трения =
больше дневников = больше данных для прогноза.

**Варианты модели:**
1. **On-device (офлайн, приватно):** TensorFlow.js + лёгкая CNN (MobileNet, дообученная
   на видах наших рыб). Плюс: работает офлайн, бесплатно. Минус: нужен датасет и обучение;
   точность на «наших» видах надо набивать.
2. **Облачный API:** отправляем фото на сервис классификации (свой Edge-эндпоинт с
   моделью, или сторонний). Плюс: точнее, проще стартовать. Минус: нужен интернет, стоимость,
   приватность фото.
3. **Гибрид (рекомендую для старта):** сначала эвристика + «предложи из частых для этого
   водоёма/сезона» (у нас уже есть данные по видам рядом!) → распознавание как ускоритель,
   не как обязательный шаг.

**Умный шорткат:** даже без ML можно резко снизить трение — предлагать при добавлении
улова **топ-виды для этого водоёма и сезона** (из `waterProfile`/`nearbySignal`). Часто
этого достаточно, чтобы выбрать в один тап. Это делаем сразу, ML — позже.

## Порядок
1. Этап 1 (фото в дневнике) — вместе, с тестом на телефоне.
2. «Умный шорткат» видов по водоёму/сезону при добавлении улова (без ML).
3. Датасет + модель (on-device TF.js или облако) — отдельный проект, когда наберём фото.
