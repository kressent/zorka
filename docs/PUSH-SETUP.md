# 🔔 Пуш-уведомления на телефон — настройка (~20 минут)

Внутри-приложенческий колокольчик уже работает. Пуш — это чтобы уведомление
прилетало на телефон, **даже когда приложение закрыто**. Основа в коде готова;
осталось твоё: сгенерировать ключи, включить отправку. По шагам.

> ⚠️ **iPhone:** пуш в вебе работает ТОЛЬКО если приложение добавлено на экран
> «Домой» (Safari → «Поделиться» → «На экран Домой») и открыто оттуда. iOS 16.4+.
> На Android/компе работает и в обычном браузере.

## 1. Сгенерировать VAPID-ключи (пара: публичный + приватный)
На компе выполни (нужен Node):
```
npx web-push generate-vapid-keys
```
Получишь **Public Key** и **Private Key**. Публичный — не секрет, приватный — секрет.

## 2. Вписать публичный ключ в приложение
В `js/config.js` в `CONFIG` замени:
```
VAPID_PUBLIC: 'СЮДА_ПУБЛИЧНЫЙ_КЛЮЧ',
```
Закоммить/запушить (или дай мне — я впишу). После этого в профиле (👤) появится
кнопка **«🔔 Пуш-уведомления на телефон»**.

## 3. Создать таблицу подписок
Supabase → SQL Editor → прогнать `supabase/013_push.sql`.

## 4. Задеплоить функцию отправки
Функция готова: `supabase/functions/push-notify/index.ts`.
```
npm i -g supabase          # если ещё нет CLI
supabase login
supabase link --project-ref jcazwvivxxlrhkguolfp
supabase secrets set VAPID_PUBLIC=<публичный> VAPID_PRIVATE=<приватный>
supabase functions deploy push-notify --no-verify-jwt
```
(SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY проставляются автоматически.)

## 5. Повесить вебхуки на лайки и комментарии
Supabase → **Database → Webhooks → Create webhook** (сделать два раза):
- Таблица **trip_likes**, событие **Insert** → тип **Supabase Edge Functions** →
  функция **push-notify**.
- Таблица **trip_comments**, событие **Insert** → та же функция.

## 6. Проверить
- На телефоне: открой приложение (на iPhone — с экрана «Домой»), 👤 → «🔔 Пуш…» →
  разреши уведомления.
- Пусть второй человек лайкнет/прокомментирует твой улов → прилетит пуш.

---

### Как это работает
Кто-то лайкнул/прокомментировал выезд → вебхук дёргает функцию → она по префиксу
`trip_key` находит владельца, берёт его push-подписки и шлёт уведомление (свои
действия не шлёт, мёртвые подписки чистит). На телефоне пуш показывает
`sw.js` (обработчики `push` / `notificationclick` уже на месте).

Если что-то не пошлётся — логи функции: Supabase → Edge Functions → push-notify → Logs.

## 🔥 Бонус: пуш «завтра жор» по прогнозу (удержание)
Утренний/вечерний пуш «собирайся — впереди отличный клёв». Считает прогноз тем же
движком, что и приложение, для точки твоего города. Готово в коде, нужно включить:

1. **Миграции** (SQL Editor, по порядку):
   - `019_push_location.sql` — координаты в подписке (куда считать прогноз).
   - `020_forecast_cron.sql` — расписание (раз в день, 15:00 UTC ≈ 18:00 МСК).
     Требует расширения `pg_cron` + `pg_net` (SQL их включит; если проект их не
     даёт — можно вместо cron дёргать функцию любым внешним планировщиком).
2. **Обновить движок в функции и задеплоить** (если движок менялся — сперва
   `node tools/bundle-push.js`, он копирует `js/{data,astro,score,forecastAlert}.js`
   в `functions/forecast-push/lib`):
   ```
   supabase functions deploy forecast-push --no-verify-jwt
   ```
   (Секреты VAPID уже стоят с push-notify — повторно не нужно.)
3. **Проверить вручную** (не дожидаясь cron):
   ```
   curl -X POST https://jcazwvivxxlrhkguolfp.supabase.co/functions/v1/forecast-push \
     -H "Authorization: Bearer <anon/publishable key>"
   ```
   Ответ `sent N`. Точка берётся из твоей подписки (обновляется, когда открываешь
   приложение с выбранным городом). Шлётся не чаще раза в сутки на устройство,
   и только если впереди день заметно лучше сегодняшнего.

### Как это работает
`forecast-push` берёт все подписки с координатами, группирует по точкам, тянет
Open-Meteo, считает `computeForecast` (та же логика, что в приложении) и
`goodDayAlert` (сильный день в ближайшие 2 дня, лучше сегодняшнего). Кому подходит —
шлёт пуш и ставит `last_fpush=сегодня` (антидубль). Логи: Edge Functions →
forecast-push → Logs.
